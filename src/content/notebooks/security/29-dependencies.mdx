Not in the lecture, and worth having, because most of the code you ship is not
yours.

```text
  your code            ~5,000 lines you reviewed
  node_modules         ~200,000 lines you did not
                       from ~1,200 maintainers you have never met
                       any of whom can push a new version tonight
```

<DoThis>

The realistic controls

- <Mint>Lockfiles committed</Mint>, and `npm ci` / `pip install -r` in CI, so the build
  is the versions you tested.
- <Mint>Automated updates</Mint> (Dependabot, Renovate) so patching is routine rather
  than a project. <Peach>Most breaches through dependencies use a fix that was
  available for months.</Peach>
- <Mint>Audit in CI</Mint> and fail on high severity, with a documented exception path
  so it does not become noise everyone mutes.
- <Mint>Pin your CI actions to a SHA</Mint>, not a tag. A tag can be moved.
- <Mint>Be suspicious of new, tiny, single-maintainer packages</Mint> in the critical
  path, and of typo-adjacent names.

</DoThis>
