```sql
CREATE TABLE tasks (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id uuid NOT NULL REFERENCES projects ON DELETE CASCADE,
  title      text NOT NULL,
  ...
);
```

The foreign key lives on the <Peach>many</Peach> side. One project, many tasks.

```text
  projects                 tasks
  ┌────────────┐           ┌──────────────────────────┐
  │ id = p1    │◀──────────│ id = t1   project_id = p1│
  └────────────┘◀──────────│ id = t2   project_id = p1│
                 ◀─────────│ id = t3   project_id = p1│
                           └──────────────────────────┘
```

`NOT NULL` on `project_id` is a modelling statement: <Peach>a task cannot exist
without a project</Peach>. If orphan tasks are legal in your domain, leave it
nullable, but decide deliberately rather than by omission.
